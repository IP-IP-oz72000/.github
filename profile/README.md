<h2>批量收费看的是阶梯，不是单价</h2>
<p>买十条和买一条，单价可能差三成。原因是供应商按阶梯定价：量越大，单条价格越低。所以批量采购的核心不是砍价，是找准阶梯的拐点。</p>
<p>拐点通常是五条、二十条、五十条。如果你的需求是十八条，凑到二十条往往比按十八条买更省，因为跨档后单价整体下降。</p>

<h2>阶梯价的三种设计</h2>
<p>第一种是纯阶梯：全部数量按所在档的单价计。第二种是分段累计：前五条按第一档，第六到二十条按第二档。第三种是一口价包：比如「二十条打包价」。</p>
<p>三种算法在同一个数量下结果不同。询价时要问清「是纯阶梯还是分段累计」，否则你算出来的价格和对方算出来的不一样。</p>

<h2>跨境电商套餐通常怎么组</h2>
<p>常见组合是「基础包加增量包」：基础包给五条或十条，价格固定；超出部分按增量单价加。这种设计对需求波动的团队友好，平时用基础包，忙时加量。</p>
<p>要注意增量单价与基础单价的差距。有的方案基础包很便宜，增量单价却高得多，实际用起来并不省。</p>

<h2>批量采购的四个注意点</h2>
<p>第一，确认计价方式。第二，确认是否支持分批交付。第三，确认中途增减如何结算。第四，确认是否支持分段（不同子网）。</p>
<p>四项里，第二项最实际：一次交付十条，其中三条不合格，谈判会很被动；分两批交付，第一批不合格可以立刻叫停。</p>

<h2>为什么量大不一定更划算</h2>
<p>因为单价降了，但总量涨了。判断是否划算的标准应该是「单账号成本」，不是总价。</p>
<p>举个例子：十条地址服务十个账号，单账号成本是单价；二十条地址服务十个账号，单账号成本翻倍，因为有一半闲置。所以采购量要跟着账号数走，不要跟着折扣走。</p>

<h2>怎么规划采购量</h2>
<p>账号数乘以一点二到一点五，向上取整到最近的阶梯档。多出来的部分用作备用和轮换。</p>
<p>如果账号数正好在拐点下方一点点，可以适当增加一两条账号的规划，让采购落在新的档位上，整体更经济。前提是这些账号确实要开。</p>

<h2>合同里的三个数字</h2>
<p>单价、总数量、以及有效期。三个数字要写清，尤其是有效期：批量套餐往往有使用期限，过期未用的部分不退。</p>
<p>另外要写清「未使用部分能否延期」。有的允许延期一次，有的不允许，差别不小。</p>

<h2>先算「够用的最小量」，再谈批量价</h2>
<p>批量采购最容易犯的错是先看折扣、后算需求。正确顺序反过来：先算出「当下真正要用的条数」，再往上找最近的阶梯。这样买回来的每一条都有归属，不会出现一半闲置的状况。</p>
<p>闲置不只是浪费钱。长期没有流量的地址容易被回收，等你真想用的时候，发现它已经不在了。所以宁可少买，也不要为了折扣囤着。</p>
<h2>常见问题</h2>
<h3>能不能拆单享受两次折扣</h3>
<p>不建议。拆单会被识别为不同订单，可能反而拿不到批量价，还可能增加管理成本。</p>
<h3>批量采购能指定不同城市吗</h3>
<p>可以，但要分别计价。不同城市的单价不同，混在一起算容易出错。</p>
<h3>中途减量怎么算</h3>
<p>看合同。多数按原价倒扣已使用部分，实际退款很少。所以采购量宁少勿多。</p>
<h3>能不能先付一部分</h3>
<p>可以谈。批量订单常见做法是分两批付款，交付一批付一批。这对双方都是约束。</p>
